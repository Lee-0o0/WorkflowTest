# 步骤参数说明

本文档基于 `WorkflowTestEngine` **当前实现**整理，描述各步骤类型在 `config_json` 中支持的字段，以及所有步骤共用的提取、断言与变量引用规则。

> 步骤定义存储于 `ts_step_definition` / `ts_hook_step_definition`；执行前会对配置、提取、断言中的 `${...}` 模板做变量替换。

---

## 1. 步骤通用字段

工作流步骤与钩子步骤除所属容器不同外，字段结构一致（工作流步骤归属工作流，钩子步骤归属组级钩子）。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `code` | string | 是 | 步骤编码，组内唯一；可通过 `steps.{code}` 引用该步骤输出 |
| `name` | string | 是 | 显示名称 |
| `type` | enum | 是 | `HTTP` / `SQL` / `DELAY` |
| `sortOrder` | int | 是 | 执行顺序，升序 |
| `enabled` | boolean | 否 | 默认 `true`；`false` 时跳过 |
| `configJson` | object | 是 | 步骤类型专属配置，见下文 |
| `extractionJson` | array | 否 | 变量提取规则，默认 `[]` |
| `assertionJson` | array | 否 | 断言规则，默认 `[]` |

### 1.1 失败行为（MVP）

当前版本**不支持**步骤级重试或失败策略配置，任一步骤失败即：

1. **工作流步骤失败**：立即终止该工作流，不再执行后续步骤；工作流执行记录与本次运行状态均为 `FAILED`。
2. **组前置钩子（`BEFORE_GROUP`）步骤失败**：不再执行组内任何工作流及组后置钩子；组执行记录与本次运行状态均为 `FAILED`。
3. **组后置钩子（`AFTER_GROUP`）步骤失败**：组执行记录与本次运行状态均为 `FAILED`（此前工作流结果保留）。

## 2. 变量引用 `${...}`

配置、提取、断言 JSON 中的字符串均支持 `${变量路径}` 模板替换（见 `VariableTemplateResolver`）。

### 2.1 可用命名空间

| 前缀 | 含义 | 示例 |
|------|------|------|
| `global.*` | `application.yml` → `workflowtest.global.*` | `${global.baseUrl}` |
| `project.*` | 项目级作用域变量 | `${project.apiKey}` |
| `group.*` | 组级配置变量 + 组级运行时提取 | `${group.baseUrl}` |
| `workflow.*` | 工作流级配置变量 + 工作流级运行时提取 | `${workflow.token}` |
| `steps.*` | 已执行步骤的输出 | `${steps.createOrder.response.status}` |
| （无前缀） | 同 `workflow.*`，仅当前工作流层 | `${baseUrl}` |

### 2.2 替换规则

1. **整段只有一个变量**（如 `"${workflow.orderId}"`）：保留变量原始类型（数字、布尔、对象等）。
2. **嵌入普通字符串**（如 `"订单 ${workflow.orderId}"`）：按字符串拼接处理。
3. **变量不存在**：步骤执行前直接失败。
4. **提取目标**：组级钩子用 `group.xxx`，工作流步骤用 `workflow.xxx`；一期仅支持单层变量名（不允许 `group.a.b` 或 `workflow.a[0]`）。
5. **同层读取**：`group.*` / `workflow.*` 优先读取运行时提取值，再回退到该层已配置的环境变量。

## 3. HTTP 步骤（`type = HTTP`）

实现类：`HttpStepExecutor`

### 3.1 `configJson` 参数

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `method` | string | 否 | `GET` | HTTP 方法，自动转大写 |
| `url` | string | 是 | — | 请求 URL，支持 `${...}` |
| `headers` | object | 否 | `{}` | 请求头，键值均为字符串 |
| `body` | string / object | 否 | 空 | 请求体；对象会序列化为 JSON 字符串；空则不发 body |
| `connectTimeoutMs` | int | 否 | `5000` | 连接超时（毫秒） |
| `readTimeoutMs` | int | 否 | `10000` | 读取超时（毫秒） |

> **当前未实现**：设计稿中的 `query`、`bodyType` 等字段；查询参数请直接写在 `url` 中。

### 3.2 配置示例

```json
{
  "method": "POST",
  "url": "${workflow.baseUrl}/orders",
  "headers": {
    "Authorization": "Bearer ${group.token}",
    "Content-Type": "application/json"
  },
  "body": {
    "skuId": "${workflow.skuId}",
    "quantity": 2
  },
  "connectTimeoutMs": 5000,
  "readTimeoutMs": 10000
}
```

### 3.3 步骤输出 `output`

```json
{
  "request": {
    "method": "POST",
    "url": "https://example.com/orders",
    "headers": { "Content-Type": "application/json" },
    "body": "{\"skuId\":\"1001\",\"quantity\":2}"
  },
  "response": {
    "status": 200,
    "headers": { "content-type": ["application/json"] },
    "body": { "data": { "orderId": 12345 } }
  },
  "elapsedMs": 128
}
```

响应体若可解析为 JSON 则存为对象，否则存为字符串。

### 3.4 提取 / 断言常用 `source`

| source | 含义 | 典型 expression |
|--------|------|-----------------|
| `OUTPUT` | 完整 output（默认） | `$.response.status` |
| `RESPONSE_BODY` | 响应体 | `$.data.orderId` |
| `RESPONSE_HEADER` | 响应头 Map | `$.content-type` |
| `STATUS_CODE` | HTTP 状态码 | 留空或 `$.response.status` |

## 4. SQL 步骤（`type = SQL`）

实现类：`SqlStepExecutor`  
数据源来自项目资源（`ts_project_resource`，类型 `DATASOURCE`），通过 `datasourceId` 引用。

### 4.1 `configJson` 参数

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `datasourceId` | long / string | 是 | — | 项目数据源 ID |
| `operation` | string | 否 | `QUERY` | `QUERY` 或 `UPDATE` |
| `sql` | string | 是 | — | SQL 语句，支持命名参数 `:name` |
| `parameters` | object | 否 | `{}` | 命名参数键值对，支持 `${...}` |
| `timeoutSeconds` | int | 否 | `10` | 查询超时（秒） |
| `maxRows` | int | 否 | `100` | `QUERY` 时最大返回行数 |

### 4.2 命名参数

SQL 中使用 `:paramName` 占位，由引擎替换为 `?` 并绑定 `parameters` 中同名键：

```sql
SELECT id, name FROM orders WHERE status = :status AND id = :id
```

```json
{
  "parameters": {
    "status": "WAIT_PAY",
    "id": "${workflow.orderId}"
  }
}
```

### 4.3 危险 SQL 限制

当数据源配置 `allowDangerousSql = false`（默认）时，语句以 `DROP` / `TRUNCATE` / `ALTER` / `CREATE` 开头会被拒绝。

### 4.4 `operation` 行为

| operation | 行为 | output 主要字段 |
|-----------|------|-----------------|
| `QUERY` | 执行查询 | `rows`（对象数组）、`rowCount` |
| `UPDATE` | 执行更新 | `updateCount` |

### 4.5 配置示例

```json
{
  "datasourceId": "1",
  "operation": "QUERY",
  "sql": "SELECT id, name FROM sample WHERE id = :id",
  "parameters": { "id": 1 },
  "timeoutSeconds": 10,
  "maxRows": 100
}
```

### 4.6 提取 / 断言常用 `source`

| source | 含义 | 典型 expression |
|--------|------|-----------------|
| `OUTPUT` | 完整 output | `$.rows` |
| `SQL_ROWS` | 结果行数组 | `$[0].id` |
| `UPDATE_COUNT` | 更新影响行数 | 留空 |

## 5. DELAY 步骤（`type = DELAY`）

实现类：`DelayStepExecutor`  
用于固定等待，常用于联调节流或简单流程编排。

### 5.1 `configJson` 参数

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `millis` | long | 否 | `1000` | 等待毫秒数，范围 **0 ~ 300000** |

### 5.2 配置示例

```json
{
  "millis": 2000
}
```

### 5.3 步骤输出

```json
{
  "delayedMs": 2000
}
```

## 6. 变量提取 `extractionJson`

实现类：`StepPostProcessor.extract`  
JSON **数组**，每项从步骤输出中提取值并写入运行时变量。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `target` | string | 是 | — | 目标变量：组级 `group.xxx`，工作流级 `workflow.xxx` |
| `source` | string | 否 | `OUTPUT` | 数据来源，见各步骤类型的 source 表 |
| `expression` | string | 否 | 空 | [JsonPath](https://github.com/json-path/JsonPath) 表达式；空则取 source 根对象 |
| `required` | boolean | 否 | `false` | 为 `true` 且提取结果为 null 时失败 |
| `defaultValue` | any | 否 | — | 提取为 null 时的默认值 |

### 示例

```json
[
  {
    "target": "workflow.orderId",
    "source": "RESPONSE_BODY",
    "expression": "$.data.orderId",
    "required": true
  },
  {
    "target": "workflow.firstName",
    "source": "SQL_ROWS",
    "expression": "$[0].name"
  }
]
```

## 7. 断言 `assertionJson`

实现类：`StepPostProcessor.assertAll`  
JSON **数组**，任一条失败则步骤失败。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `source` | string | 否 | `OUTPUT` | 同提取规则 |
| `expression` | string | 否 | 空 | JsonPath；空则取 source 根对象作为 actual |
| `operator` | string | 否 | `EQUALS` | 比较操作符，见下表 |
| `expected` | any | 否 | — | 期望值 |

### 7.1 支持的操作符 `operator`

| 操作符 | 说明 |
|--------|------|
| `EQUALS` | 相等（数字按 BigDecimal 比较） |
| `NOT_EQUALS` | 不相等 |
| `CONTAINS` | 实际值字符串包含期望值 |
| `NOT_CONTAINS` | 实际值字符串不包含期望值 |
| `EXISTS` / `NOT_NULL` | 实际值非 null |
| `NOT_EXISTS` / `IS_NULL` | 实际值为 null |
| `GREATER_THAN` | 实际值 > 期望值 |
| `GREATER_THAN_OR_EQUAL` | 实际值 ≥ 期望值 |
| `LESS_THAN` | 实际值 < 期望值 |
| `LESS_THAN_OR_EQUAL` | 实际值 ≤ 期望值 |
| `MATCHES_REGEX` | 实际值字符串匹配正则（`expected` 为正则） |
| `SIZE_EQUALS` | 集合/Map 的 size 或字符串长度等于期望值 |

### 示例

```json
[
  {
    "source": "STATUS_CODE",
    "operator": "EQUALS",
    "expected": 200
  },
  {
    "source": "RESPONSE_BODY",
    "expression": "$.data.status",
    "operator": "EQUALS",
    "expected": "SUCCESS"
  },
  {
    "source": "SQL_ROWS",
    "expression": "$",
    "operator": "SIZE_EQUALS",
    "expected": 1
  }
]
```

## 8. 完整步骤示例

```json
{
  "code": "createOrder",
  "name": "创建订单",
  "type": "HTTP",
  "sortOrder": 1,
  "enabled": true,
  "configJson": {
    "method": "POST",
    "url": "${workflow.baseUrl}/orders",
    "headers": { "Content-Type": "application/json" },
    "body": { "amount": "${workflow.amount}" },
    "readTimeoutMs": 10000
  },
  "extractionJson": [
    {
      "target": "workflow.orderId",
      "source": "RESPONSE_BODY",
      "expression": "$.data.id",
      "required": true
    }
  ],
  "assertionJson": [
    {
      "source": "STATUS_CODE",
      "operator": "EQUALS",
      "expected": 200
    }
  ]
}
```
