# 步骤参数说明

本文档基于 `WorkflowTestEngine` **当前实现**整理，描述各步骤类型在 `config_json` 中支持的字段，以及所有步骤共用的提取、断言与变量引用规则。

> 步骤定义存储于 `ts_step_definition` / `ts_hook_step_definition`；执行前会对配置、提取、断言中的 `${...}` 模板做变量替换，再解析为 `executor/config/` 下的强类型配置（如 `HttpStepConfig`）。

---

## 1. 步骤通用字段

工作流步骤与钩子步骤除所属容器不同外，字段结构一致（工作流步骤归属工作流，组钩子步骤归属组级钩子，**项目钩子步骤**归属项目级钩子 `BEFORE_EACH_GROUP`）。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `code` | string | 是 | 步骤编码，组内唯一；可通过 `steps.{code}` 引用该步骤输出 |
| `name` | string | 是 | 显示名称 |
| `type` | enum | 是 | `HTTP` / `SQL` / `DELAY` / `SET_VAR` / `DELETE_VAR` |
| `sortOrder` | int | 是 | 执行顺序，升序 |
| `enabled` | boolean | 否 | 默认 `true`；`false` 时跳过 |
| `configJson` | object | 是 | 步骤类型专属配置，见下文 |
| `extractionJson` | array | 否 | 变量提取规则，默认 `[]` |
| `assertionJson` | array | 否 | 断言规则，默认 `[]` |

### 1.1 失败行为（MVP）

当前版本**不支持**步骤级重试或失败策略配置，任一步骤失败即：

1. **工作流步骤失败**：立即终止该工作流，不再执行后续步骤；工作流执行记录与本次运行状态均为 `FAILED`。
2. **组前置钩子（`BEFORE_GROUP`）步骤失败**：不再执行组内任何工作流及组后置钩子；组执行记录与本次运行状态均为 `FAILED`。
3. **组后置钩子（`AFTER_GROUP`）步骤失败**：组执行记录与本次运行状态均为 `FAILED`（此前工作流结果保留）。
4. **项目钩子（`BEFORE_EACH_GROUP`）步骤失败**：当前组不再执行，项目执行终止为 `FAILED`。

### 1.2 项目资源（执行计划 `resources`）

执行前 Server 会将项目下所有启用的资源写入执行计划 `resources`，Engine 通过 `RuntimeResourceManager.merge()` 注册，**不**在执行期读取 `ts_project_resource` 表。

| 资源类型 | 计划字段 | 步骤引用方式 |
|----------|----------|--------------|
| `DATASOURCE` | `resources.datasources` | SQL 步骤 `configJson.datasourceId` |
| `FILE` | `resources.files` | 模板 `${file.资源名称}` 或 `${file:资源ID}` |

文件资源配置含 `path`（绝对路径）、`encoding`（默认 `UTF-8`）。引用时按配置编码读取全文，可用于 HTTP `body` 等字段。

## 2. 变量引用 `${...}`

配置、提取、断言 JSON 中的字符串均支持 `${变量路径}` 模板替换（见 `VariableTemplateResolver`）。

### 2.1 可用命名空间

| 前缀 | 含义 | 示例 |
|------|------|------|
| `global.*` | 执行计划 `environment.global`（由 Server 组装） | `${global.baseUrl}` |
| `project.*` | 项目级作用域变量 | `${project.apiKey}` |
| `group.*` | 组级配置变量 + 组级运行时提取 | `${group.baseUrl}` |
| `workflow.*` | 工作流级配置变量 + 工作流级运行时提取 | `${workflow.token}` |
| `steps.*` | 已执行步骤的输出 | `${steps.createOrder.response.status}` |
| `file.*` / `file:` | 项目文件资源（执行计划 `resources.files`） | `${file.requestBody}`、`${file:12}` |
| （无前缀） | 同 `workflow.*`，仅当前工作流层 | `${baseUrl}` |

### 2.2 替换规则

1. **整段只有一个变量**（如 `"${workflow.orderId}"`）：保留变量原始类型（数字、布尔、对象等）。
2. **嵌入普通字符串**（如 `"订单 ${workflow.orderId}"`）：按字符串拼接处理。
3. **变量不存在**：步骤执行前直接失败。
4. **提取目标**：按执行位置限制作用域（见 §5.2 / §8）；一期仅支持单层变量名（不允许 `group.a.b` 或 `workflow.a[0]`）。
5. **同层读取**：`group.*` / `workflow.*` / `project.*` 优先读取运行时提取值，再回退到该层已配置的环境变量。

## 3. HTTP 步骤（`type = HTTP`）

实现类：`HttpStepExecutor`

### 3.1 `configJson` 参数

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `method` | string | 否 | `GET` | HTTP 方法，自动转大写 |
| `url` | string | 是 | — | 请求 URL，支持 `${...}` |
| `headers` | object | 否 | `{}` | 请求头，键值均为字符串 |
| `body` | string / object | 否 | 空 | 请求体；对象会序列化为 JSON 字符串；空则不发 body |
| `connectTimeoutMs` | int | 否 | `5000` | 连接超时（毫秒） |
| `readTimeoutMs` | int | 否 | `10000` | 读取超时（毫秒） |

> **当前未实现**：设计稿中的 `query`、`bodyType` 等字段；查询参数请直接写在 `url` 中。

### 3.2 配置示例

```json
{
  "method": "POST",
  "url": "${workflow.baseUrl}/orders",
  "headers": {
    "Authorization": "Bearer ${group.token}",
    "Content-Type": "application/json"
  },
  "body": {
    "skuId": "${workflow.skuId}",
    "quantity": 2
  },
  "connectTimeoutMs": 5000,
  "readTimeoutMs": 10000
}
```

### 3.3 步骤输出 `output`

```json
{
  "request": {
    "method": "POST",
    "url": "https://example.com/orders",
    "headers": { "Content-Type": "application/json" },
    "body": "{\"skuId\":\"1001\",\"quantity\":2}"
  },
  "response": {
    "status": 200,
    "headers": { "content-type": ["application/json"] },
    "body": { "data": { "orderId": 12345 } }
  },
  "elapsedMs": 128
}
```

响应体若可解析为 JSON 则存为对象，否则存为字符串。

### 3.4 提取 / 断言常用 `source`

| source | 含义 | 典型 expression |
|--------|------|-----------------|
| `OUTPUT` | 完整 output（默认） | `$.response.status` |
| `RESPONSE_BODY` | 响应体 | `$.data.orderId` |
| `RESPONSE_HEADER` | 响应头 Map | `$.content-type` |
| `STATUS_CODE` | HTTP 状态码 | 留空或 `$.response.status` |

## 4. SQL 步骤（`type = SQL`）

实现类：`SqlStepExecutor`  
数据源来自项目资源（`ts_project_resource`，类型 `DATASOURCE`），通过 `datasourceId` 引用。

### 4.1 `configJson` 参数

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `datasourceId` | long / string | 是 | — | 项目数据源 ID |
| `operation` | string | 否 | `QUERY` | `QUERY` 或 `UPDATE` |
| `sql` | string | 是 | — | SQL 语句，支持命名参数 `:name` |
| `timeoutSeconds` | int | 否 | `10` | 查询超时（秒） |
| `maxRows` | int | 否 | `100` | `QUERY` 时最大返回行数 |

> **已移除** `parameters` 字段。SQL 命名参数从环境变量解析，规则与 `${...}` 一致（工作流 → 组 → 项目 → 全局）。

### 4.2 命名参数

SQL 中使用 `:paramName` 占位，引擎按参数名从环境变量取值并绑定：

```sql
SELECT id, name FROM orders WHERE status = :status AND id = :orderId
```

需事先通过配置变量或 **SET_VAR** 步骤写入 `status`、`orderId` 等变量。`:orderId` 等价于读取 `${orderId}` / `${workflow.orderId}` 的解析结果。

### 4.3 危险 SQL 限制

当数据源配置 `allowDangerousSql = false`（默认）时，语句以 `DROP` / `TRUNCATE` / `ALTER` / `CREATE` 开头会被拒绝。

### 4.4 `operation` 行为

| operation | 行为 | output 主要字段 |
|-----------|------|-----------------|
| `QUERY` | 执行查询 | `rows`（对象数组）、`rowCount` |
| `UPDATE` | 执行更新 | `updateCount` |

### 4.5 配置示例

```json
{
  "datasourceId": "1",
  "operation": "QUERY",
  "sql": "SELECT id, name FROM sample WHERE id = :orderId",
  "timeoutSeconds": 10,
  "maxRows": 100
}
```

### 4.6 提取 / 断言常用 `source`

| source | 含义 | 典型 expression |
|--------|------|-----------------|
| `OUTPUT` | 完整 output | `$.rows` |
| `SQL_ROWS` | 结果行数组 | `$[0].id` |
| `UPDATE_COUNT` | 更新影响行数 | 留空 |

## 5. SET_VAR 步骤（`type = SET_VAR`，环境变量赋值）

实现类：`SetVarStepExecutor`  
在运行时向 **项目级**、**组级** 或 **工作流级** 环境变量写入值，供后续步骤通过 `${...}` 或 SQL `:param` 引用。

### 5.1 `configJson` 参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `variables` | object | 是 | 键为赋值目标；**无前缀时默认写入当前执行层**（见 5.2） |

### 5.2 作用域规则与生命周期

| 执行位置 | 允许的 target 写法 | 生命周期 |
|----------|-------------------|----------|
| 工作流步骤 | `orderId`（等同 `workflow.orderId`）、`workflow.*` | 当前工作流执行结束销毁 |
| 组钩子步骤 | `group.*`（无前缀默认组层，可写 `token` 等同 `group.token`） | 当前组执行结束销毁 |
| 项目钩子（`BEFORE_EACH_GROUP`） | `project.*`（无前缀默认项目层） | 当前组执行结束销毁（下一组前重新执行项目钩子） |

不支持向 `global.*` 运行时赋值（由 Server 配置管理）。`project.*` 在组钩子/工作流步骤中**只读**（读取 Server 配置 + 项目钩子运行时写入值）。

### 5.3 配置示例

**工作流步骤：**

```json
{
  "variables": {
    "orderId": 1001,
    "status": "WAIT_PAY",
    "token": "${steps.login.response.body.token}"
  }
}
```

**组钩子：**

```json
{
  "variables": {
    "group.channel": "${global.defaultChannel}",
    "token": "abc"
  }
}
```

**项目钩子：**

```json
{
  "variables": {
    "project.batchId": "${global.currentBatch}",
    "batchId": 20250924
  }
}
```

### 5.4 output

output 为本次写入的键值快照，便于调试；后续步骤读取仍以环境变量解析为准。

## 6. DELETE_VAR 步骤（`type = DELETE_VAR`，删除环境变量）

实现类：`DeleteVarStepExecutor`  
删除运行时 **项目级**、**组级** 或 **工作流级** 环境变量（仅影响本次执行内存，不修改 Server 配置的 global/project 静态变量）。

### 6.1 `configJson` 参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `variables` | string[] | 是 | 待删除变量目标；规则同 SET_VAR（§5.2） |

### 6.2 作用域规则

与 **SET_VAR** 相同：各执行位置只能删除本层运行时变量；`global.*` 禁止。

### 6.3 配置示例

**工作流步骤：**

```json
{
  "variables": ["orderId", "workflow.tempFlag"]
}
```

**组钩子：**

```json
{
  "variables": ["group.token", "token"]
}
```

### 6.4 output

```json
{
  "removed": ["orderId", "group.token"],
  "missing": ["workflow.tempFlag"]
}
```

- `removed`：本次成功删除的运行时变量
- `missing`：目标合法但当前不存在（不视为步骤失败）

---

## 6.5 项目钩子 `BEFORE_EACH_GROUP`

**执行时机**：项目级执行时，在**每个工作流组开始之前**运行一次（先于该组的 `BEFORE_GROUP` 钩子）。

**用途**：为即将执行的组准备项目运行时变量（如批次号、临时 Token），变量在本组全部工作流与组钩子执行完成后自动清空。

**步骤定义**：存储于 `ts_project_hook_step_definition`，字段与工作流/组钩子步骤相同；API 前缀 `/api/project-hooks/{id}/steps`。

## 7. DELAY 步骤（`type = DELAY`）

实现类：`DelayStepExecutor`  
用于固定等待，常用于联调节流或简单流程编排。

### 7.1 `configJson` 参数

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `millis` | long | 否 | `1000` | 等待毫秒数，范围 **0 ~ 300000** |

### 7.2 配置示例

```json
{
  "millis": 2000
}
```

### 7.3 步骤输出

```json
{
  "delayedMs": 2000
}
```

## 8. 变量提取 `extractionJson`

实现类：`StepPostProcessor.extract`  
JSON **数组**，每项从步骤输出中提取值并写入运行时变量。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `target` | string | 是 | — | 写入目标：规则同 SET_VAR（§5.2）；禁止 `global.*` |
| `source` | string | 否 | `OUTPUT` | 数据来源，见各步骤类型的 source 表 |
| `expression` | string | 否 | 空 | [JsonPath](https://github.com/json-path/JsonPath) 表达式；空则取 source 根对象 |
| `required` | boolean | 否 | `false` | 为 `true` 且提取结果为 null 时失败 |
| `defaultValue` | any | 否 | — | 提取为 null 时的默认值 |

### 示例

```json
[
  {
    "target": "workflow.orderId",
    "source": "RESPONSE_BODY",
    "expression": "$.data.orderId",
    "required": true
  },
  {
    "target": "workflow.firstName",
    "source": "SQL_ROWS",
    "expression": "$[0].name"
  }
]
```

## 9. 断言 `assertionJson`

实现类：`StepPostProcessor.assertAll`  
JSON **数组**，任一条失败则步骤失败。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `source` | string | 否 | `OUTPUT` | 同提取规则 |
| `expression` | string | 否 | 空 | JsonPath；空则取 source 根对象作为 actual |
| `operator` | string | 否 | `EQUALS` | 比较操作符，见下表 |
| `expected` | any | 否 | — | 期望值 |

### 9.1 支持的操作符 `operator`

| 操作符 | 说明 |
|--------|------|
| `EQUALS` | 相等（数字按 BigDecimal 比较） |
| `NOT_EQUALS` | 不相等 |
| `CONTAINS` | 实际值字符串包含期望值 |
| `NOT_CONTAINS` | 实际值字符串不包含期望值 |
| `EXISTS` / `NOT_NULL` | 实际值非 null |
| `NOT_EXISTS` / `IS_NULL` | 实际值为 null |
| `GREATER_THAN` | 实际值 > 期望值 |
| `GREATER_THAN_OR_EQUAL` | 实际值 ≥ 期望值 |
| `LESS_THAN` | 实际值 < 期望值 |
| `LESS_THAN_OR_EQUAL` | 实际值 ≤ 期望值 |
| `MATCHES_REGEX` | 实际值字符串匹配正则（`expected` 为正则） |
| `SIZE_EQUALS` | 集合/Map 的 size 或字符串长度等于期望值 |

### 示例

```json
[
  {
    "source": "STATUS_CODE",
    "operator": "EQUALS",
    "expected": 200
  },
  {
    "source": "RESPONSE_BODY",
    "expression": "$.data.status",
    "operator": "EQUALS",
    "expected": "SUCCESS"
  },
  {
    "source": "SQL_ROWS",
    "expression": "$",
    "operator": "SIZE_EQUALS",
    "expected": 1
  }
]
```

## 10. 完整步骤示例

```json
{
  "code": "createOrder",
  "name": "创建订单",
  "type": "HTTP",
  "sortOrder": 1,
  "enabled": true,
  "configJson": {
    "method": "POST",
    "url": "${workflow.baseUrl}/orders",
    "headers": { "Content-Type": "application/json" },
    "body": { "amount": "${workflow.amount}" },
    "readTimeoutMs": 10000
  },
  "extractionJson": [
    {
      "target": "workflow.orderId",
      "source": "RESPONSE_BODY",
      "expression": "$.data.id",
      "required": true
    }
  ],
  "assertionJson": [
    {
      "source": "STATUS_CODE",
      "operator": "EQUALS",
      "expected": 200
    }
  ]
}
```
